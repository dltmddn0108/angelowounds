# 데이터베이스 기초

데이터베이스는 애플리케이션의 핵심이다. RDBMS와 NoSQL의 차이를 이해하고, 상황에 맞게 선택해야 한다.

## SQL 기본

```sql
-- 인덱스를 활용한 조회
SELECT u.name, COUNT(o.id) AS order_count
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE u.created_at > '2024-01-01'
GROUP BY u.id
HAVING order_count > 5
ORDER BY order_count DESC;
```

## 인덱스 (Indexes)

인덱스는 읽기 성능을 높이지만 쓰기 성능을 낮춘다. B-Tree 인덱스가 기본이며, 전문 검색에는 GIN 인덱스가 적합하다.

### 인덱스 설계 원칙

1. WHERE 절에 자주 사용되는 컬럼에 인덱스 생성
2. 카디널리티가 높은 컬럼이 효과적
3. 복합 인덱스의 컬럼 순서가 중요 (leftmost prefix rule)

## 정규화 vs 비정규화

정규화는 데이터 중복을 줄이고, 비정규화는 조회 성능을 최적화한다. 실무에서는 3NF까지 정규화한 후 필요한 부분만 비정규화하는 것이 일반적.

## ORM 사용 시 주의점

ORM은 편리하지만 N+1 쿼리 문제를 유발하기 쉽다. Prisma나 TypeORM 사용 시 생성되는 SQL을 반드시 확인해야 한다. REST API 설계 시 데이터 접근 패턴을 먼저 고려해야 하는 이유이기도 하다.

> [!info] 성능 모니터링
> `EXPLAIN ANALYZE`를 습관적으로 사용하자. 쿼리 실행 계획을 읽을 수 있어야 진짜 최적화가 가능하다.
