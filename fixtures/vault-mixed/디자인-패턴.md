# 디자인 패턴

소프트웨어 디자인 패턴은 반복적으로 발생하는 설계 문제에 대한 일반적인 해결책이다. GoF(Gang of Four)의 23가지 패턴이 가장 유명하다.

## 생성 패턴 (Creational)

### Singleton

전역 상태를 관리할 때 유용하지만 테스트를 어렵게 만든다. Node.js에서는 모듈 캐싱이 사실상 싱글턴 역할을 한다.

### Factory

객체 생성 로직을 캡슐화한다. TypeScript의 제네릭과 함께 사용하면 타입 안전한 팩토리를 만들 수 있다.

## 구조 패턴 (Structural)

### Adapter

외부 라이브러리를 래핑하여 내부 인터페이스에 맞추는 패턴. REST API 클라이언트를 추상화할 때 자주 사용한다.

### Observer

이벤트 기반 시스템의 핵심. Node.js의 EventEmitter, React의 상태 변경 알림 모두 Observer 패턴이다.

```typescript
class EventBus {
  private listeners = new Map<string, Set<Function>>();

  on(event: string, fn: Function) {
    if (!this.listeners.has(event)) this.listeners.set(event, new Set());
    this.listeners.get(event)!.add(fn);
  }

  emit(event: string, ...args: any[]) {
    this.listeners.get(event)?.forEach(fn => fn(...args));
  }
}
```

## 현대적 관점

클래스 기반 패턴 중 상당수는 함수형 프로그래밍에서 더 간결하게 표현된다. 클린 코드의 원칙과 결합하면 유지보수성이 크게 향상된다.

> [!info] 패턴 남용 주의
> 패턴은 도구일 뿐이다. 문제에 맞는 패턴을 선택해야 하며, 패턴 자체가 목적이 되면 오히려 코드가 복잡해진다.
